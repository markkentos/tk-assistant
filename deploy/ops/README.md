# Операции прод-сервера (одноразовые патчи, применённые по SSH)

Каждый скрипт — точечное изменение конфигов на домашнем ПК
(mark0@192.168.1.170, `D:\pet-project\tk-assistant\deploy\`), применённое
один раз во время настройки. **Итоговое состояние уже зафиксировано** в
`docker-compose.yml` и `Caddyfile` — повторный запуск не нужен. Файлы
оставлены как история операций и шаблоны для переноса на другой сервер.

Применение: скопировать файл на ПК и выполнить через powershell —
изменения вносятся точечным replace по якорной строке, с защитой от
повторного применения.

| Скрипт | Что сделал |
|---|---|
| `fix_rag_models.ps1` | маунт HF-кэша моделей (D:\models\hf) в контейнер rag |
| `fix_e5_embedder.ps1` | EMBEDDER_MODEL=intfloat/multilingual-e5-base для rag |
| `fix_caddy_pure.ps1` | маршрут /v1 → llama-server (**чистая e6v2**) |
| `fix_caddy_rag.ps1` | маршрут /v1 → rag (**текущий прод: e6v2+RAG**) |
| `fix_llama_e6v2.ps1` | llama-server: база Qwen2.5 Q4_K_M + LoRA e6v2 |
| `fix_llama_lora_flag.ps1` | исправление флага `-l` → `--lora` |
| `fix_llama_shard.ps1` | `-m` на первый шард GGUF (серия подхватывается сама) |
| `fix_llama_ctx6144.ps1` | контекст 4096 → 6144 (мульти-статейный промпт) |

`fix_caddy_pure.ps1` / `fix_caddy_rag.ps1` — **переиспользуемые**:
это переключатель прод-режима «чистая e6v2 ↔ e6v2+RAG».

# Ручная вычитка — протокол

Зачем: автофильтры ловят грубое, но не «правду». Вычитка даёт честный ответ на вопрос
интервьюера «как обеспечивал качество данных?» — с цифрами: «сгенерировал N, фильтры
отсеяли M, вычитка нашла K% брака, починил X».

## Что делать

1. `python data/scripts/review_sample.py --n 500` — создаёт два CSV в `data/review/`:
   - `review_500_*.csv` — случайная стратифицированная выборка из датасета;
   - `review_filtered_out_50_*.csv` — пары, отсеянные фильтрами (проверяем, что фильтры
     не режут хорошее и действительно режут плохое).
2. Заполни колонку `verdict` (OK / BAD_ANSWER / BAD_QUESTION / BAD_REF / OTHER)
   и, при браке, `note`. Сверяй каждый ответ с текстом статьи (колонка `article` →
   `data/processed/tk_articles.json` или zakonrf.info).
3. **50 отфильтрованных**: это пары, которые фильтры выбросили. Отметь, сколько из них
   на самом деле хорошие (ложные срабатывания).

## Что фиксировать по итогам (пойдёт в README и карточку датасета)

- доля брака в выборке (по типам вердиктов);
- доля ложных срабатываний фильтров;
- типовые ошибки генератора (примеры — в error analysis этапа 4);
- действия: что правил в промптах/фильтрах после первой сотни статей.

## Правила честности

- Вычитка идёт ДО сплита и не зависит от него; правки по итогам вычитки вносятся
  в пайплайн (промпты/фильтры) и датасет перегенерируется/перепроверяется.
- Test-сплит не используется ни для чего до этапа 4.

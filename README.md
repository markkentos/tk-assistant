# tk-assistant — QLoRA-дообучение 7B LLM для ответов по трудовому праву РФ

Дообучаю открытую 7B-модель (Qwen2.5-7B-Instruct), чтобы она отвечала на вопросы по трудовому праву
РФ: **точно, со ссылкой на конкретную статью ТК РФ, в стабильном проверяемом формате** — на
собственном датасете QA-пар, сгенерированном и отфильтрованном по тексту кодекса.

**Цель проекта:** tuned-модель объективно лучше base-модели на моём бенчмарке — с таблицей метрик,
а не словами «стало лучше».

---

## Пайплайн

```
ТК РФ (текст, 534 статьи)
  → парсинг на статьи (номер, заголовок, текст, глава)          data/scripts/download_tk.py, parse_articles.py
  → генерация QA-пар сильной LLM через API (4 на статью)        data/scripts/generate_qa.py
  → фильтры: формат (+авточинка ссылок) / заземление            data/scripts/filters.py
  → LLM-предскрин: третий независимый прогон                    data/scripts/prescreen.py
  → дедупликация (fuzzy + опц. эмбеддинги)                      data/scripts/dedup.py
  → ручная разметка: флагнутые + случайная сотня                data/scripts/finalize_dataset.py
  → стратифицированный сплит train/val/test                     data/scripts/split_dataset.py
  → QLoRA (Unsloth + PEFT + TRL, 4-bit NF4, T4, fp16)           src/train_qlora.py
  → бенчмарк base vs tuned + LLM-as-judge (другая модель)       eval/*
```

## Результаты

*Судья — GigaChat-Max, заземлён на текст статьи; бенчмарк — 100 вопросов из test-сплита;
ROUGE-L против верифицированных эталонов.*

| Метрика | base (few-shot) | tuned (QLoRA, 1 эпоха) |
|---|---|---|
| Judge score (1–5), mean | 1.93 | **2.15** |
| — фактическая точность | 1.58 | **2.08** |
| — полнота | 1.56 | **1.83** |
| — корректность ссылки | 1.02 | 1.04 |
| — формат | 3.54 | **3.64** |
| Галлюцинации, % | 86% | **58%** |
| Неверные ссылки, % | 95% | 97% |
| ROUGE-L vs эталон | 0.040 | **0.052** |

**Δ judge: +0.22 (+11%), галлюцинации −28 п.п.** После 1 эпохи модель выучила формат
и стиль (ссылка присутствует в 100% ответов), галлюцинаций стало существенно меньше,
но сопоставление «тема → номер статьи» ещё не закрепилось — идёт эксперимент с 3 эпохами.

## Формат данных

Каждая QA-пара — JSONL-запись:

```json
{
  "id": "qa_000123",
  "article": "80",
  "chapter": 13,
  "question_type": "situational",
  "question": "Может ли работодатель уволить работника, который подал заявление по собственному желанию, а через неделю передумал?",
  "answer": "...",
  "source_article_url": "https://www.zakonrf.info/tk/80/"
}
```

**Единый формат ответа** (его же требует системный промпт и проверяет судья):

```
<Краткий ответ одним предложением.>
<Обоснование: 1–3 предложения со ссылкой в формате «ст. N ТК РФ».>
```

## Дисциплина

- **test-сплит не открывается** до этапа 4: не используется ни в обучении, ни для тюнинга.
- Эталоны бенчмарка: сгенерированы LLM **заземлённо** (в промпт передан текст статьи) и
  **верифицированы вручную** (verdict OK / исправление на каждую сотню вопросов). Судья
  оценивает по тексту статьи, а не только по эталону — заземление снижает риск подгонки.
- Разметка вычитки ведётся в CSV (см. `data/review/README.md`).
- Каждый эксперимент обучения = отдельный чекпоинт + логи в TensorBoard.

## Качество данных

Протокол: **формат (+авточинка ссылок) → заземление второй моделью → LLM-предскрин →
ручная разметка флагнутых и случайной выборки**.

| Стадия | Результат |
|---|---|
| Генерация | 2075 пар по 521 активной статье (~4 на статью) |
| Формат | −201 (короткие ответы без обоснования); 539 ответов без ссылки починены автоматически |
| Заземление | −237 (11.4%: галлюцинации, контент не из статьи) |
| Предскрин | 14 флагов, **13 подтверждено вручную** (точность 93%) |
| Дедупликация | −9 самоповторов |
| Ручная разметка случайной сотни | **0% брака** → остаточный дефект <3% (верхняя граница 95% ДИ) |
| **Итог** | **1615 пара** → train 1259 / val 178 / test 178 |

Отказ от fuzzy-самосогласия из исходного плана — осознанно: замер на 160 парах показал,
что галлюцинации проходят (чекер-модель их повторяет), а корректные перефразировки
отсеиваются. Вместо него — предскрин с другим промптом + ручная разметка.

Эталоны бенчмарка: LLM-генерация по тексту статьи + ручная верификация каждой сотни.
test-сплит закрыт до этапа 4.

## Как воспроизвести

```bash
pip install -r requirements.txt

# Этап 1: данные
python data/scripts/download_tk.py          # скачает ТК РФ в data/raw/tk/
python data/scripts/parse_articles.py       # статьи → data/processed/tk_articles.json
python data/scripts/generate_qa.py --config configs/generate_qa.yaml --shuffle
python data/scripts/filters.py --config configs/filters.yaml
python data/scripts/prescreen.py            # третий прогон → флаги для ручной разметки
python data/scripts/dedup.py
# ручная разметка data/review/*.csv (флагнутые + случайная сотня)
python data/scripts/finalize_dataset.py     # удалить подтверждённый брак
python data/scripts/split_dataset.py --input data/processed/qa_final.jsonl
python data/scripts/stats.py

# Этап 2: baseline (до обучения!)
python eval/build_benchmark.py --n 100      # → вручную заполнить эталоны
python src/generate_answers.py --mode base --input eval/benchmark.jsonl --output eval/runs/answers_base.jsonl
python eval/judge.py --answers eval/runs/answers_base.jsonl --name base

# Этап 3: обучение (на T4, Colab/Kaggle)
pip install -r requirements-colab.txt
python src/train_qlora.py --config configs/train_qlora.yaml

# Этап 4: оценка tuned + сравнение
python src/generate_answers.py --mode tuned --adapter outputs/adapter_e1_lr2e-4 --input eval/benchmark.jsonl --output eval/runs/answers_tuned.jsonl
python eval/judge.py --answers eval/runs/answers_tuned.jsonl --name tuned
python eval/compare.py
```

Секреты — в файле `.env` в корне (шаблон: `.env.example`, файл в `.gitignore`):
`GIGACHAT_CREDENTIALS` (ключ авторизации GigaChat API), `OPENROUTER_API_KEY`, `HF_TOKEN`.

## Среда обучения и особенности

- GPU: Colab **T4** (16 ГБ) / Kaggle T4×2. Проверка окружения пройдена (2026-10-27,
  `notebooks/00_t4_smoke_test.ipynb`): Qwen2.5-7B в 4-bit NF4 занимает **7.5 GB VRAM**.
- У T4 **нет bf16** → обучение в **fp16** (Unsloth подхватит автоматически; в конфиге — явно).
- Форматирование данных — строго `tokenizer.apply_chat_template`, без ручной склейки строк.
- Обучение 3–5k примеров на T4: ~2–5 часов — влезает в одну сессию.

## Данные и источники

- Текст ТК РФ: zakonrf.info (действующая редакция, скачано 2026-10) — **534 статьи**
  (424 основных номера + 110 подпунктов вида 19.1/22.1; в устаревших источниках фигурирует
  «~415 статей»), 526 активных + 8 утративших силу, ~794 тыс. символов. Качается скриптом,
  точечно сверяется с официальной публикацией. Официальный текст ТК РФ как акт государственного
  органа находится в публичном достоянии; комментарии сторонних сайтов в датасет не включаются.
- Сгенерированный датасет будет выложен на HuggingFace Datasets с карточкой (план, фильтры,
  статистика вычитки).

# tk-assistant — QLoRA-дообучение 7B LLM для ответов по трудовому праву РФ

Дообучаю открытую 7B-модель (Qwen2.5-7B-Instruct), чтобы она отвечала на вопросы по трудовому праву
РФ: **точно, со ссылкой на конкретную статью ТК РФ, в стабильном проверяемом формате** — на
собственном датасете QA-пар, сгенерированном и отфильтрованном по тексту кодекса.

**Цель проекта:** tuned-модель объективно лучше base-модели на моём бенчмарке — с таблицей метрик,
а не словами «стало лучше».

---

## Пайплайн

```
ТК РФ (текст, 534 статьи)
  → парсинг на статьи (номер, заголовок, текст, глава)          data/scripts/download_tk.py, parse_articles.py
  → генерация QA-пар сильной LLM через API (4 на статью)        data/scripts/generate_qa.py
  → фильтры: формат (+авточинка ссылок) / заземление            data/scripts/filters.py
  → LLM-предскрин: третий независимый прогон                    data/scripts/prescreen.py
  → дедупликация (fuzzy + опц. эмбеддинги)                      data/scripts/dedup.py
  → ручная разметка: флагнутые + случайная сотня                data/scripts/finalize_dataset.py
  → стратифицированный сплит train/val/test                     data/scripts/split_dataset.py
  → QLoRA (Unsloth + PEFT + TRL, 4-bit NF4, T4, fp16)           src/train_qlora.py
  → экспорт в GGUF: база + LoRA, llama-server (CUDA, дом/ПК)    deploy/
  → RAG-сервис: e5-эмбеддер + BM25 + соседи статей → топ-5      deploy/rag/
  → бенчмарк base vs tuned vs tuned+RAG + LLM-as-judge          eval/*
```

## Результаты

*Судья — GigaChat-Max, заземлён на текст статьи; бенчмарк — 100 вопросов из test-сплита;
ROUGE-L против верифицированных эталонов. Слепая человеческая оценка — 30 пар.*

| Метрика | base (few-shot) | QLoRA 1 эп | QLoRA 3 эп | **QLoRA 6 эп, датасет v2** | e3+RAG (top-3)* | **e6v2+RAG (5 статей)** |
|---|---|---|---|---|---|---|
| Judge score (1–5), mean | 1.93 | 2.15 | 2.23 | **3.21** | 2.83 | **3.38** |
| — фактическая точность | 1.58 | 2.08 | 2.02 | **2.91** | 2.67 | **3.27** |
| — полнота | 1.56 | 1.83 | 1.77 | **2.64** | 2.40 | **2.98** |
| — корректность ссылки | 1.02 | 1.04 | 1.33 | **3.03** | 2.65 ↓ | **3.29** |
| — формат | 3.54 | 3.64 | 3.82 | **4.28** | 3.60 | 4.00 |
| Галлюцинации, % | 86% | 58% | 64% | **45%** | 43% | **22%** |
| Неверные ссылки, % | 95% | 97% | 89% | **38%** | 55% ↑ | **28%** |
| ROUGE-L vs эталон | 0.040 | 0.052 | 0.167 | **0.557** | 0.446 ↓ | **0.544** |

\* e3+RAG — ранее эта колонка ошибочно публиковалась как «+ RAG»: генерация шла на e3,
а не на e6v2 (подробности в примечаниях к `eval/results.md`).
e6v2+RAG: судья оценил 91 вопрос, 11 инфра-сбоев засчитаны как худшие; **только по 80
валидным ответам — overall 3.71** (лучше чистой e6v2 по всем пяти метрикам).

**Итог: judge +66% к base, точных ссылок на статью 2% → 59% (объективная проверка
регуляркой), ROUGE-L ×14.** Слепая человеческая оценка (30 пар): tuned выигрывает
83% решённых пар у base. **С RAG поверх e6v2 — judge 3.38 (на валидных 3.71),
галлюцинации 45% → 22%, неверные ссылки 38% → 28% — это текущая прод-конфигурация.**

**Ключевые выводы экспериментов:**

1. **Формат выучивается за 1 эпоху**, стилистическая стабильность — после 3.
2. **Данные важнее эпох:** 3 эпохи на 1615 парах дали 11% точных ссылок; 6 эпох на
   3997 парах (v2, ~8 пар/статью для покрытых статей) — **59%**. Мемоизация
   «тема → номер статьи» растёт от объёма повторов, не от числа эпох.
3. **Потолок чистого QLoRA:** оставшиеся 38% неверных ссылок — статьи, не покрытые
   датасетом, и редкие темы. Лечится расширением покрытия или RAG (следующий шаг).
4. Слепая человеческая оценка подтвердила направление судьи.
5. **RAG поверх QLoRA улучшает ответы — если измерять честно.** Первый замер
   («+RAG, judge 2.83») оказался модельно-смещённым: генерация шла на e3, а не на
   e6v2 (e6v2 тогда ещё не был квантован). На честных парах RAG помогал обеим
   моделям: e3 2.23 → 2.83; **e6v2 3.21 → 3.38 (на валидных ответах 3.71)**,
   галлюцинации 45% → 22%, неверные ссылки 38% → 28%. Ключ к результату — ретрив:
   эмбеддер multilingual-e5 + гибрид BM25/семантика + соседи статей дают правильную
   статью в контексте в **82%** случаев (было 68% на MiniLM/top-1).
6. **Прод-конфигурация демо — e6v2 + RAG** (caddy ведёт /v1 в RAG-сервис, тот — в
   llama-server с LoRA-GGUF). Откат на чистую e6v2 — одна строка в Caddyfile.
   Следующий шаг качества — RAG-native файнтюн: контекст в обучающих примерах
   (датасет готов, `notebooks/04`).

## Человеческая слепая оценка и error analysis

**Слепая разметка 30 пар** (человек не знал, где base, где tuned):

| | Победы |
|---|---|
| tuned_e3 | **19 из 23 решённых (83%)** |
| base | 4 (17%) |
| оба плохи | 7 (23%) |

Человек независимо подтвердил направление судейской оценки. Важная деталь протокола:
разметка была **намеренно мягкой** — «приемлемо» засчитывалось как победа ответа,
`both_bad` ставился только если оба ответа полностью неверны. Мягкая шкала смещает
результат к ничьей, то есть **83% побед tuned_e3 — консервативная оценка**. Судья при
этом строгий (средние баллы 1.9–2.2 из 5) — два оценщика с противоположной калибровкой
сходятся в направлении различия.

7 пар `both_bad` (23%) — «твёрдое ядро» провалов обоих моделей: как правило, вопросы
к редким статьям, требующие точных цифр и сроков, которых нет ни в базе знаний модели,
ни в заученном датасете. Именно эти кейсы — аргумент за RAG в развитии проекта.

**Error analysis (ключевые находки):**

1. **3 эпохи учат мемоизации, а не только стилю.** Точные ссылки на статью: 2% (base) →
   3% (1 эпоха) → **11%** (3 эпохи); judge-критерий «ссылка» +30%; ROUGE-L ×4.
2. **Промахи тематические, а не случайные:** 36% неверных ссылок — в пределах ±5 номеров
   от правильной статьи (модель выучила кластеры тем: пособия, гарантии, отпуска).
3. **Трейд-офф длительности обучения:** 3 эпохи лучше запоминают факты, но чуть больше
   галлюцинируют (64% vs 58% у 1 эпохи) — уверенность растёт быстрее точности.
4. **Хрестоматийная галлюцинация base:** на вопрос про работу несовершеннолетнего в выходной
   Qwen2.5-Instruct (few-shot) ответил на **китайском языке** со ссылкой на Трудовой кодекс
   КНР (bm_050). QLoRA-модель этот дрейф вылечила.
5. **Ограничение подхода:** чистое QLoRA без RAG заучивает лишь часть сопоставления
   «тема → номер статьи» из 521 статей. Числовая калибровка судьи (человек vs judge по
   1–5) не проводилась — направление оценок судьи подтверждено слепой человеческой
   оценкой. RAG поверх tuned-модели реализован и измерен (см. «Результаты»): judge 3.38.

## Формат данных

Каждая QA-пара — JSONL-запись:

```json
{
  "id": "qa_000003",
  "article": "241",
  "chapter": 39,
  "question_type": "situational",
  "question": "Может ли работодатель взыскать с меня сумму ущерба больше моего среднего месячного заработка?",
  "answer": "Работодатель вправе требовать возмещения ущерба лишь в размере вашего среднего месячного заработка, если иное не предусмотрено законодательством.\nОбоснование: ст. 241 ТК РФ.",
  "source_article_url": "https://www.zakonrf.info/tk/241/"
}
```

**Единый формат ответа** (его же требует системный промпт и проверяет судья):

```
<Краткий ответ одним предложением.>
<Обоснование: 1–3 предложения со ссылкой в формате «ст. N ТК РФ».>
```

## Дисциплина

- **test-сплит не открывается** до этапа 4: не используется ни в обучении, ни для тюнинга.
- Эталоны бенчмарка: сгенерированы LLM **заземлённо** (в промпт передан текст статьи) и
  **верифицированы вручную** (verdict OK / исправление на каждую сотню вопросов). Судья
  оценивает по тексту статьи, а не только по эталону — заземление снижает риск подгонки.
- Разметка вычитки ведётся в CSV (см. `data/review/README.md`).
- Каждый эксперимент обучения = отдельный чекпоинт + логи в TensorBoard.

## Качество данных

Протокол: **формат (+авточинка ссылок) → заземление второй моделью → LLM-предскрин →
ручная разметка флагнутых и случайной выборки**.

| Стадия | Результат |
|---|---|
| Генерация | 2075 пар по 521 активной статье (~4 на статью) |
| Формат | −201 (короткие ответы без обоснования); 539 ответов без ссылки починены автоматически |
| Заземление | −237 (11.4%: галлюцинации, контент не из статьи) |
| Предскрин | 14 флагов, **13 подтверждено вручную** (точность 93%) |
| Дедупликация | −9 самоповторов |
| Ручная разметка случайной сотни | **0% брака** → остаточный дефект <3% (верхняя граница 95% ДИ) |
| **Итог** | **1615 пара** → train 1259 / val 178 / test 178 |

Отказ от fuzzy-самосогласия из исходного плана — осознанно: замер на 160 парах показал,
что галлюцинации проходят (чекер-модель их повторяет), а корректные перефразировки
отсеиваются. Вместо него — предскрин с другим промптом + ручная разметка.

Эталоны бенчмарка: LLM-генерация по тексту статьи + ручная верификация каждой сотни.
test-сплит закрыт до этапа 4.

## Как воспроизвести

```bash
pip install -r requirements.txt

# Этап 1: данные
python data/scripts/download_tk.py          # скачает ТК РФ в data/raw/tk/
python data/scripts/parse_articles.py       # статьи → data/processed/tk_articles.json
python data/scripts/generate_qa.py --config configs/generate_qa.yaml --shuffle
python data/scripts/filters.py --config configs/filters.yaml
python data/scripts/prescreen.py            # третий прогон → флаги для ручной разметки
python data/scripts/dedup.py
# ручная разметка data/review/*.csv (флагнутые + случайная сотня)
python data/scripts/finalize_dataset.py     # удалить подтверждённый брак
python data/scripts/split_dataset.py --input data/processed/qa_final.jsonl
python data/scripts/stats.py

# Этап 2: baseline (до обучения!)
python eval/build_benchmark.py --n 100      # → вручную заполнить эталоны
python src/generate_answers.py --mode base --input eval/benchmark.jsonl --output eval/runs/answers_base.jsonl
python eval/judge.py --answers eval/runs/answers_base.jsonl --name base

# Этап 3: обучение (на T4, Colab/Kaggle)
pip install -r requirements-colab.txt
python src/train_qlora.py --config configs/train_qlora.yaml

# Этап 4: оценка tuned + сравнение
python src/generate_answers.py --mode tuned --adapter outputs/adapter_e1_lr2e-4 --input eval/benchmark.jsonl --output eval/runs/answers_tuned.jsonl
python eval/judge.py --answers eval/runs/answers_tuned.jsonl --name tuned
python eval/compare.py --names "base tuned"

# Этап 5: e6v2 + RAG (деплой — см. deploy/README.md; RAG-сервис должен работать)
python eval/bench_rag.py                     # 100 вопросов через RAG-сервис (с резюмой)
python eval/judge.py --answers eval/runs/answers_e6v2_rag.jsonl --name e6v2_rag
python eval/compare.py --names "base tuned tuned_e3 tuned_e6v2 e3_rag e6v2_rag"
python eval/retrieval_recall.py              # recall@k ретрива (BASE=адрес RAG-сервиса)
```

Секреты — в файле `.env` в корне (шаблон: `.env.example`, файл в `.gitignore`):
`GIGACHAT_CREDENTIALS` (ключ авторизации GigaChat API), `OPENROUTER_API_KEY`, `HF_TOKEN`.

## Среда обучения и особенности

- GPU: Colab **T4** (16 ГБ) / Kaggle T4×2. Проверка окружения пройдена (2026-10-27,
  `notebooks/00_t4_smoke_test.ipynb`): Qwen2.5-7B в 4-bit NF4 занимает **7.5 GB VRAM**.
- У T4 **нет bf16** → обучение в **fp16** (Unsloth подхватит автоматически; в конфиге — явно).
- Форматирование данных — строго `tokenizer.apply_chat_template`, без ручной склейки строк.
- Обучение 3–5k примеров на T4: ~2–5 часов — влезает в одну сессию.
- **⚠️ Colab:** пиновать `pip install "unsloth<2026.11"` — релиз 2026.11.1 ставит
  torch 2.11+cu130, с которым xformers не грузится и T4 деградирует до ~30 с/шаг
  (вместо ~4) с оффлоадом градиентов.

## Данные и источники

- Текст ТК РФ: zakonrf.info (действующая редакция, скачано 2026-10) — **534 статьи**
  (424 основных номера + 110 подпунктов вида 19.1/22.1; в устаревших источниках фигурирует
  «~415 статей»), 526 активных + 8 утративших силу, ~794 тыс. символов. Качается скриптом,
  точечно сверяется с официальной публикацией. Официальный текст ТК РФ как акт государственного
  органа находится в публичном достоянии; комментарии сторонних сайтов в датасет не включаются.
- Сгенерированный датасет будет выложен на HuggingFace Datasets с карточкой (план, фильтры,
  статистика вычитки).
